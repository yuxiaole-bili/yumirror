# 流程积木与模板参考

> 本文件由 `python scripts/gen_docs.py` 从 `shared/flow_engine.py` **自动生成**，请勿手工编辑。
> CI 里可以跑 `python scripts/gen_docs.py --check` 校验文档是否与代码同步。

当前共 **30 个积木**、**40 个内置模板**，分 8 类：
备份 / 版本 / 校验 / 同步 / 清理 / 通知 / 巡检 / 系统。

编辑器入口：客户端面板 → 流程编辑器（`/editor`，拖拽式）或积木模式（`/blocks`）。

## 三、模板步骤明细

### 备份

#### 完整管道　`full_pipeline`

哈希/路径/服务端/HTTP 全链路流水线示例　·　**Full pipeline** — End-to-end example: hash / path / server / HTTP

- **车道 哈希检验**（2 步）
  - 🔑 本地哈希　`get_file_hash`　`file_path`='{{_full_path}}', `result_var`='_local_hash'
  - ☁ 服务端哈希　`get_server_hash`　`file_path`='{{_relpath}}', `result_var`='_server_hash'
- **车道 信息收集**（2 步）
  - 📋 文件大小　`get_path_info`　`source`='local', `file_path`='{{_relpath}}', `info_type`='size', `result_var`='_file_size_bytes'
  - 📋 是否存在　`get_path_info`　`source`='local', `file_path`='{{_relpath}}', `info_type`='exists', `result_var`='_file_exists'
- **车道 通知发送**（2 步）
  - 🌐 发送通知　`http_request`　`url`='https://example.com/webhook', `method`='POST', `body`='{"file":"{{_relpath}}","hash":"{{_local_hash}}","size":"{{_file_size_bytes}}"}', `result_var`='_notify_resp'
  - 📋 通知结果　`log`　`message`='📤 通知: {{_notify_resp}}'
- 合并点：`[1, 2]`

#### 自动备份到服务端　`auto_backup`

变更自动备份（哈希比对）　·　**Auto backup to server** — Backup on change, compared by hash

- **车道 备份校验**（4 步）
  - 🔑 本地哈希　`get_file_hash`　`file_path`='{{_full_path}}', `result_var`='_local_hash'
  - ☁ 校验服务端备份　`backup_to_server`　`file_path`='{{_relpath}}', `result_var`='_backup_ok'
  - ⚖ 是否已有备份　`compare`　`left`='{{_backup_ok}}', `op`='==', `right`='true'
  - 📋 备份结论　`log`　`message`='☁ {{_relpath}} 服务端备份: {{_backup_ok}} | 本地哈希 {{_local_hash}}'

#### ① 变更即备份　`backup_on_change`

变更即上传服务端并校验哈希　·　**① Backup on change** — Upload to server and verify the hash on every change


#### ② 每日打包归档　`backup_zip_daily`

整目录打包 zip 后上传归档　·　**② Daily zip archive** — Zip the whole folder and upload it as an archive


#### ③ 整目录批量备份　`bulk_backup_folder`

逐文件批量上传，首次补齐历史文件　·　**③ Bulk folder backup** — Upload file by file — good for the first seeding


#### ④ 备份清单报告　`backup_manifest_report`

生成含 SHA256 的清单并上传留档　·　**④ Backup manifest report** — Build a manifest with SHA256 and upload it


#### ⑨ 加密备份　`encrypted_backup`

先加密再上传，服务端只存密文　·　**⑨ Encrypted backup** — Encrypt before upload — the server only stores ciphertext


#### ⑫ 按类型分类归档　`classify_archive_by_type`

扫描同步目录，按扩展名把文件归到 归档/图片、归档/文档、归档/其他　·　**⑫ Archive by type** — Scan the sync folder and sort files into archive/images, archive/docs, archive/other


#### ⑯ 大文件压缩后上传　`large_file_compress_upload`

超过 1MB 的文件先打包成 zip 再上传，小文件直接传　·　**⑯ Compress large files** — Files over 1 MB are zipped before upload, small ones go straight through


#### ⑲ 变更留档到 vault　`vault_on_change`

每次变更把当前内容按时间戳存一份到 vault 目录，并打一个版本点　·　**⑲ Vault every change** — Keep a timestamped copy of every change in a vault folder and mark a version


### 版本

#### ⑩ 一键回滚上一版　`rollback_latest`

一键回滚到上一版并取回本地　·　**⑩ Roll back one version** — Roll back to the previous version and fetch it locally


#### ⑪ 版本巡检　`version_audit`

逐文件检查服务端历史版本数　·　**⑪ Version audit** — Check how many versions the server keeps per file


#### ⑭ 夜间快照归档　`nightly_snapshot_rotate`

把整个同步目录打包成带时间戳的 zip，上传服务端并打一个版本点　·　**⑭ Nightly snapshot** — Zip the whole sync folder with a timestamp, upload it and mark a version


#### ⑮ 加密归档并核对版本　`encrypted_archive_verify`

  - 📋 记录服务端哈希　`log`　`message`='☁ 服务端: {{_server_hash}}'

## 四、模板里可用的变量

| 变量 | 含义 |
|---|---|
| `{{_full_path}}` | 触发文件在本地的绝对路径 |
| `{{_relpath}}` | 相对同步目录的路径（服务端备份就用它） |
| `{{_folder}}` | 触发文件所在同步文件夹的**名字** |
| `{{_client_dir}}` | 客户端程序目录 |
| `{{_timestamp}}` | 当前整数秒时间戳（可用于文件名/版本标记） |
| `{{_local_hash}}` `{{_server_hash}}` `{{_peer_hash}}` | 各步骤写入的哈希结果变量 |
| `@folder:名字` | 取该同步文件夹在**本机**的绝对路径 |

密钥类参数（`passphrase_secret`）填的是**配置项名字**，不是口令本身：
口令放在 `client/config.json` 的 `backup_passphrase` / `backup_key_file`，积木通过名字去取，
不会出现在流程文件、日志或接口返回里。
