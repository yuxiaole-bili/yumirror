# 安全模型

这份文档说明 yumirror **保护什么、不保护什么**，以及这些结论是怎么验证出来的。
动手部署前花三分钟读完，能省掉后面很多误会。

## 一句话定位

**面向可信局域网的自用/折腾型工具**：同一个组里的机器互相信任，服务端管理员是可信的。
它不是零信任系统，也不适合直接暴露到公网。

## 信任假设

| 角色 | 假设 |
|---|---|
| 服务端 | 由你或你信任的人管理；`server/config.json`、`users.json`、`certs/` 不被外人读取 |
| 同组客户端 | 互相信任（同组可以互推文件、互取哈希，这是"镜像"功能的前提） |
| 组外机器 | **不可信**：可能扫描端口、尝试入组、投毒、做中间人 |
| 网络 | **不可信**（可能被嗅探、被 ARP 欺骗），但可用 TLS 保护内容 |
| 工坊里的流程 | 来源不明的流程视为**代码**，安装前必须人工看一眼 |

## 防护与验证

| 威胁 | 防护 | 怎么验证的 |
|---|---|---|
| 同网段嗅探文件内容 | TCP 走 TLS（默认开）；服务端自签证书 + 客户端 SHA256 指纹固定 | 3 台 KVM 同二层网段：攻击机 ARP 双向欺骗做中间人后 tcpdump。**加固前抓到明文文件内容（命中 6 次）与 `relpath`/`sha256` 元数据；加固后明文与元数据均 0 命中** |
| 中间人换证书 | 客户端 TOFU：首次连接固定指纹，之后不符即拒绝 | `tests/security_test.py` 用错误指纹的客户端尝试连接 → 拒绝（`connected=False`） |
| 明文客户端/老版本降级连接 | 服务端强制 TLS：明文连接连应用层都进不去 | 明文探针拿不到任何应用层响应；攻击机明文注入脚本直接 `ConnectionResetError` |
| 知道组名就入组、往别人目录写文件 | 可选组密钥（服务端 `group_keys` + 客户端 `group_key`） | KVM 实测：无密钥入组被拒 `status=rejected`、文件没进受害者目录；带正确密钥的合法客户端不受影响 |
| 匿名者投毒/删除共享方案 | 工坊写操作（上传/删除）需要登录；列出/下载保持开放 | 跨机实测：`/api/workshop/upload` 与 `delete` 返回 401 |
| 未授权读管理数据 | 面板首页、`/api/admin/*`、设备/组/状态/备份清单都要登录 | 跨机实测：全部 401 / 302 |
| 口令被彩虹表反查 | PBKDF2-HMAC-SHA256（12 万次 + 随机盐），旧哈希登录时透明升级 | 单元断言 `users.json` 中不是裸 SHA-256 |
| 投毒文件名 → 面板 XSS | 文件名/用户名进内联 JS 前做 JS 字符串转义（`jsq`） | 往同步目录投放带单引号的文件名，检查两个面板的转义 |
| 路径穿越写文件 | 所有落盘/读取都做 `commonpath` 校验与路径净化 | 裸协议 `FILE_CREATE ../../pwned.txt`、组名穿越、版本号穿越、客户端文件 API 越界，全部被拒 |
| 未鉴权面板变成 RCE | 「执行命令」积木默认禁用，需显式 `allow_command_block` | 默认配置下命令不落地；显式开启后仍可用（功能没被修死） |
| 面板被嵌入/被嗅探登录 | 安全响应头（nosniff / X-Frame-Options / CSP）、`/api/*` 不缓存、登录限速 429、可选面板 TLS | 断言响应头字段与 6 次失败后的 429 |

## 明确不防的

- **拿到服务端机器的人**：`certs/server.key`、`users.json`、备份目录都是明文存放在服务端磁盘上；磁盘加密是宿主机的责任。
- **服务端管理员**：他可以读所有备份（这是集中备份的固有属性）。
- **同组内的恶意客户端**：同组互信是设计前提；组密钥只挡组外盲注，不区分组内成员。
- **已安装的恶意流程**：流程等于代码，`run_command` 能执行命令、`http_request` 能外发数据——安装前必须自己审。
- **公网暴露**：没有任何针对公网扫描/爆破的加固（无限速持久化、无 fail2ban、无 WAF）。

## 部署加固清单

1. 防火墙限制 `9999/8086/8087` 只在可信网段，或用 SSH 隧道访问面板；
2. 客户端面板保持 `127.0.0.1`；要开放就先配 `account`；
3. 每个组配 `group_key`，别和组名一起发在群里；
4. 首次连接核对服务端打印的证书指纹；
5. 服务端面板开放到局域网时打开 `panel_tls`；
6. 重要文件用加密积木先加密再同步（内容加密，**文件名等元数据仍是明文**）；
7. 备份 `users.json` 与 `certs/`，并定期轮换证书（换完要在客户端清 `tls.fingerprint` 重新固定）。
